Ndimi REST API reference

Endpoints

GET /api/health/ Health check — Django service + MongoDB (public, no auth)
GET /api/config/ Signed-in user, enabled languages, demo setup
POST /api/config/setup/ Upload demo videos & script — requires Can change demo setup
GET /api/projects/ List own projects (all projects with Can see every user's projects)
POST /api/projects/ Create project — body: {"name":"…","target_language":"…"}
GET /api/dubs/ List dub jobs for current user
POST /api/dubs/ Create dub — multipart: file or source_url, target_language, source_language, review, clone_voices, num_speakers, glossary JSON
GET /api/dubs/<id>/ Job status, stages, speakers, transcript lines, events
DELETE /api/dubs/<id>/ Delete job (also removes cloned voices from ElevenLabs)
PATCH /api/dubs/<id>/segments/<n>/ Edit transcript segment — translated_text, speaker_id, start, end
PATCH /api/dubs/<id>/speakers/<pk>/ Edit speaker — name, voice_id
POST /api/dubs/<id>/approve/ Approve reviewed script → generate voices
POST /api/dubs/<id>/regenerate/ Re-voice lines marked "needs new voice" and re-render
POST /api/dubs/<id>/cancel/ Cancel a running job
POST /api/dubs/<id>/retry/ Retry a failed job (skips completed stages)
GET /api/dubs/<id>/download/video|audio|subtitles|source-subtitles|source/ Stream or download output — add ?download=1 to force save
GET /api/manage/<section>/ Staff: list / read settings section — drives in-app Settings UI
Authentication: All endpoints except /api/health/ require a signed-in session (401 otherwise) and the Can use the dubbing tool permission (403 otherwise). State-changing calls must include the X-CSRFToken header (read it from the csrftoken cookie).
